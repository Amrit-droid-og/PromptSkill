## ⚡ The Hard Truth About AI Prompting

Most people prompt AI like this:

> *"Hey, build me an authentication flow with JWT in Node.js and Express."*

And here is what happens next:
- ❌ The AI spits out a **400-line rewrite** of your file that breaks existing imports.
- ❌ It invents non-existent NPM packages or uses deprecated syntax from 2021.
- ❌ It silently catches and swallows errors with `catch (e) {}`.
- ❌ It writes "tautological" tests that pass even when your business logic is broken.
- ❌ You spend the next 2 hours untangling regressions you can't explain.

**The problem isn't the model. The problem is the lack of an engineering harness around the model.**

Models are probabilistic text engines. When you give them vague instructions and unconstrained scope, they fill the silence with plausible-sounding hallucinations.

**`PROMPTSKILL.md` solves this permanently.** It is a single, portable, plug-and-play instruction system designed to enforce senior-level rigor, verifiable contracts, and atomic changes across **every single AI interaction**.

## 🧭 The Core Philosophy

```
Spec first. Design second. Gates third. Small diffs fourth. Tests always.
```

1. **The AI never owns architecture, requirements, or merges.** The AI generates drafts; the human owns contracts, gates, and verification.
2. **The model is interchangeable; the process is state-of-the-art.** Whether you run Claude 3.7 Sonnet, GPT-4o, Gemini 2.5 / 3.8, DeepSeek R1, or local models, `PromptSkill` enforces the same unwavering standard.
3. **One prompt = one behavior = one diff.** No sprawling multi-file refactors in a single breath.
4. **Smallest sufficient context.** Stop dumping your entire codebase into the prompt window. Feed only what matters.
5. **If it can't be tested, it doesn't get merged.**

## 📐 The 6 Rs Framework

Every high-quality prompt generated by or through `PromptSkill` adheres to the **6 Rs**. If any R is missing, the model will fill the gap with confident guesses:

| Component | What It Is | Why It Matters |
|---|---|---|
| **1. Role** | Specific domain persona (*e.g., Staff Security Engineer, Senior Rust Architect*) | Eliminates casual advice; establishes tone and depth. |
| **2. Request** | Exactly one behavior, acceptance criteria, and explicit non-goals | Prevents scope creep and multi-responsibility bloat. |
| **3. Reality** | Exact file paths, signatures, schemas, runtime versions, stack traces | Grounds the model in real code rather than assumptions. |
| **4. Rules** | Coding style, error patterns, zero unapproved dependencies policy | Prevents rogue library installs and bad patterns. |
| **5. References** | One good codebase pattern, one anti-pattern, official doc snippet | Steers output towards your team's established idioms. |
| **6. Results** | Test commands, verification steps, diff-only requirement | Makes output instantly verifiable before touching `git`. |

## 📦 What's Inside `PROMPTSKILL.md`

`PROMPTSKILL.md` contains zero corporate buzzwords. It is a dense, high-signal instruction manual containing:

### 1. Ready-to-Use Universal Templates
- **Contract Critique Prompt (§4.1):** Put a spec in front of the AI and demand it find ambiguities, edge cases, and missing failure modes *before* anyone writes code.
- **Design Options & Trade-offs Prompt (§4.2):** Generate 3 distinct architectural options with failure modes, test strategies, and rejection rationale.
- **Context Pack Template (§4.3):** The gold standard for feeding minimal, high-precision context into any AI coding tool.
- **Implementation Prompt with Tests (§4.4):** Test-first implementation enforcing unified diffs and explicit upfront assumptions.
- **Root-Cause Bug Fix Prompt (§4.5):** Requires root-cause diagnosis in one paragraph before presenting a fix + regression test.
- **Behavior-Preserving Refactor Prompt (§4.6):** Strict invariant enforcement where public interfaces and existing tests cannot change.
- **Adversarial / Hostile Review Prompt (§4.7):** Explicitly tells the AI: *"Do not praise. Hunt for bugs, race conditions, silent catches, and hallucinated APIs."*
- **Test Generation Prompt (§4.8):** Comprehensive test suites covering happy paths, edge cases, and failure modes without tautologies.

### 2. End-to-End Task Library (§5)
A cheat sheet mapping what exact context to feed the AI for:
- Product Specs & PRDs
- User Stories & Acceptance Criteria
- Database Schemas & Migrations
- API Design & Contracts
- Feature Implementation & Bug Fixing
- Performance Budgets & Profiling
- Security Reviews & Threat Modeling
- Observability & Metrics
- Release Notes & Documentation

### 3. The 12 Traps & How to Catch Them (§8)
A survival guide against common LLM traps:
- Hallucinated APIs → *Grep verification*
- Deprecated patterns → *Doc checks*
- Scope creep in diffs → *Unified diff boundary enforcement*
- Tautological tests → *Negative validation testing*
- Sycophantic agreement → *Pre-implementation critique*
- Context rot → *Hard reset at ~20 turns*

### 4. The One Habit (§12)
> After every generation, ask:  
> **"What is the riskiest line in this diff, and how would I prove it's correct?"**  
> *If you cannot answer, you are not done.*

## 🚀 How to Use PromptSkill

### Method 1: Drop It Into Your AI Agent / Coding Assistant (Recommended)
You can directly load `PROMPTSKILL.md` into any agent or IDE assistant:

- **Cursor / Windsurf**: Add `PROMPTSKILL.md` to your root or reference it in `.cursorrules` / `.windsurfrules`.
- **Claude Code**: Keep `PROMPTSKILL.md` in your repo and add a pointer to it in `CLAUDE.md`.
- **Aider / OpenCode / Antigravity**: Pass `PROMPTSKILL.md` as context or a custom skill.
- **GitHub Copilot**: Add it to `.github/copilot-instructions.md`.

### Method 2: System Prompt in ChatGPT / Claude Projects / Gemini
1. Open your project settings or custom instructions in **ChatGPT**, **Claude Projects**, or **Gemini**.
2. Copy and paste the entire contents of [`PROMPTSKILL.md`](PROMPTSKILL.md).
3. Whenever you ask the AI to write prompts, create tickets, or generate code, it will automatically operate under these rules.

### Method 3: On-Demand Prompt Execution
Simply prompt your AI with:
```text
I am attaching PROMPTSKILL.md. 
Read §4.4 and generate an implementation prompt for [feature], 
using the Context Pack format in §4.3.
```

## ⚖️ The PromptSkill Difference: Before & After

### Without PromptSkill:
```text
Can you add rate limiting to our auth endpoint?
```
> **What you get:** 150 lines of boilerplate, a new library added to `package.json` without asking, in-memory counters that fail across distributed clusters, and zero tests.

### With PromptSkill:
```text
ROLE: Senior backend engineer on auth-service.
TASK: Add IP-based rate limiting to POST /api/v1/auth/login.
ACCEPTANCE CRITERIA:
- 5 attempts per minute per IP before returning HTTP 429 Too Many Requests.
- Includes Retry-After header.
- Uses existing Redis client in src/lib/redis.ts.
NON-GOALS:
- Do not modify user session logic.
- Do not add new third-party dependencies.
ENVIRONMENT: Node.js v20, Express v4.19, ioredis v5.3.
OUTPUT: Unified diff for src/middleware/rateLimit.ts and unit tests in tests/rateLimit.test.ts only. State assumptions at top.
```
> **What you get:** A clean, 25-line atomic diff, zero unexpected packages, edge case handling for proxies, and tests validating both 200 OK and 429 Too Many Requests.
